# 03. 콜드스타트 전략

> **이 장르는 거의 항상 여기서 죽는다.**
> 게임이 재밌어도, UI가 예뻐도, 방에 사람이 없으면 아무 의미가 없다.
> 이 문서는 그것만 다룬다.

**전제: 참가자는 전부 실제 사람이다.** 봇·AI·더미 참가자는 만들지 않는다. 가짜 사람으로 방을 채우는 선택지가 없으므로, 이 문서의 모든 전략은 **진짜 사람을 같은 시간·같은 방에 겹치게 하는 것** 하나로 수렴한다.

---

## 1. 문제

### 1.1 죽음의 나선

```
방이 비어 있다
   → 들어온 사람이 30초 기다리다 나간다
      → 다음 사람이 와도 여전히 비어 있다
         → 아무도 안 남는다
```

한 바퀴 도는 데 1분이면 충분하다. 그리고 이 나선은 **한 번 돌기 시작하면 콘텐츠로 못 막는다.** 문제가 아무리 좋아도 혼자 맞히면 재미가 없다.

### 1.2 데일리 게임과의 결정적 차이

Wordle류는 **혼자 해도 완결된다.** 동접 1명이어도 게임이 성립하고, 결과 공유가 다음 사람을 데려온다.

실시간 파티게임은 **동접이 곧 제품**이다. 동접 3명과 동접 300명은 다른 게임이다. 같은 코드, 같은 문제, 전혀 다른 경험.

### 1.3 게임별 최소 인원

| 게임 | 성립 | 재미있음 | 최적 |
|---|---|---|---|
| 초성 퀴즈 | 2 | 4 | 5~8 |
| 그 해 | 2 | 4 | 5~8 |
| 단어 연상 | 3 (출제자 1 + 맞히는 사람 2) | 5 | 6~8 |

**여기가 첫 번째 설계 결정이다. 최소 인원을 2명으로 못 박는다.**
채팅으로 답을 외치는 게임은 둘이면 이미 성립한다. "4명 모여야 시작"으로 잡으면 초기에는 영원히 시작되지 않는다. 2명이면 시작하고, 3·4번째 사람은 **진행 중에 난입**시킨다 (§5).

팀전 4:4는 8명이 필요해 가장 취약하다. 그래서 4:4는 **초대 방 중심**으로 설계한다 — 단톡방 8명이 그대로 한 판이 되는 경로가 랜덤 매칭보다 훨씬 현실적이다 (§6). 인원이 홀수면 빈자리를 메우지 않고 **한 명이 이번 판을 쉬고 다음 판에 우선 배정**된다 (01 문서 §6.5.1).

## 2. 다섯 개의 축

가짜 참가자라는 카드가 없으므로, 다섯 축은 전부 **사람을 겹치게 하는** 수단이다.

| # | 축 | 하는 일 |
|---|---|---|
| 1 | **프라임타임 집중** | 같은 시간에 오게 만든다 |
| 2 | **뭉치기 압력** | 온 사람을 같은 방에 넣는다 |
| 3 | **난입과 관전** | 기다리는 시간을 0으로 만든다 |
| 4 | **초대 우선** | 한 명이 아니라 단톡방 단위로 데려온다 |
| 5 | **혼자 모드** | 사람이 없는 순간에 붙잡아 둔다 |

**1·2번이 하중을 다 받는다.** 봇이 있는 설계에서는 그것이 "3명을 6명으로" 만들어 주는 완충재 노릇을 한다. 그게 없으니 **분산을 막는 것**이 유일한 완충재다. 동접 10명이 방 5개에 흩어지면 전부 죽고, 방 2개에 모이면 둘 다 산다. 같은 10명이다.

---

## 3. 축 1 — 프라임타임 집중

### 3.1 24시간 균등 운영은 자살이다

동접 20명이 24시간에 퍼지면 시간당 1명이다. 같은 20명이 저녁 2시간에 몰리면 **동시 10명**이다. 방 두 개가 꽉 찬다.

### 3.2 운영 시간

| 구간 | 시간 | 성격 |
|---|---|---|
| **골든타임** | 21:00 ~ 23:00 | 전 게임 · 랭크 · 팀전 개방 |
| 서브타임 | 12:30 ~ 13:30 | 점심. 초성 퀴즈만 |
| 비수기 | 그 외 | 혼자 모드 + 초대 방만 |

비수기에도 방을 만들 수는 있다. 다만 **공개 방 목록에 노출되지 않고**, 랭크는 잠긴다. 랭크는 사람이 확실히 있는 시간에만 열려야 공정하다.

### 3.3 장치

- **오늘의 개장 시각**을 첫 화면 상단에 항상 띄운다
- 개장 10분 전 **웹 푸시** — "9시 개장. 오늘의 게임은 초성 퀴즈"
- 개장 직후 5분간 **경험치 2배** — 늦게 오면 손해라는 감각
- 비수기에 들어온 사람에게는 **다음 개장까지 남은 시간**과 예약 버튼

### 3.4 개장 연출

개장 순간에 사람이 동시에 쏟아져야 한다. 그러려면 **개장 전에 대기 인원을 보여줘야** 한다.

```
    9시 개장까지  04:12

    지금 대기 중   14명
    ────────────────────
    [ 대기열에 서기 ]
```

대기 중인 사람 수는 **실제 접속자 수만** 센다. 부풀리지 않는다. 숫자가 작으면 작은 대로 보여주는 게, 들켰을 때 잃는 것보다 싸다.

### 3.5 추적 지표

| 지표 | 정의 | 경보 |
|---|---|---|
| **프라임타임 집중도** | 골든타임 세션 / 전체 세션 | < 50% |
| 피크 동시 접속 | 골든타임 최댓값 | 목표 대비 |
| 개장 5분 내 방 생성 수 | — | 0 이면 푸시가 안 먹는 것 |

## 4. 축 2 — 뭉치기 압력

**이 축이 실제로 콜드스타트를 버티게 한다.**

### 4.1 원칙

> 사람은 흩어지려 하고, 시스템은 모아야 한다.

방 목록을 그냥 보여주면 사람은 **빈 방을 새로 만든다.** 아무도 없는 방이 편하기 때문이다. 그러면 동접 10명이 방 8개가 된다.

### 4.2 규칙

```
1. 사람이 있는 방을 목록 맨 위에 고정
   → 정렬 기준은 "최근"이 아니라 "사람 수 내림차순"

2. 빈 방은 목록에 아예 안 띄운다
   → 만들 수는 있다. 다만 코드로 초대해야 들어온다

3. 새 방 만들기 버튼은 2순위
   → 1순위는 [바로 참가] — 가장 사람 많은 방에 즉시 입장

4. 정원이 안 찬 방이 하나라도 있으면 새 방 생성 전에 한 번 되묻는다
   → "지금 3명이 기다리는 방이 있어요"  [들어가기] [그래도 새로 만들기]
   → 막는 게 아니라 한 번만 되묻는다. 두 번은 안 묻는다

5. 5분간 혼자인 방은 자동 해체
   → 방장을 [바로 참가] 로 옮겨 준다
```

### 4.3 [바로 참가]가 1순위인 이유

방 목록을 훑는 행동 자체가 이탈 지점이다. 목록을 보면 "여기 사람 적네"라는 판단이 생기고, 그 판단은 대부분 나가는 쪽으로 끝난다. **판단을 없애고 그냥 넣는다.**

### 4.4 추적 지표

| 지표 | 정의 | 경보 |
|---|---|---|
| **★ 사람 있는 방을 본 비율** | 첫 방문자 중 다른 사람이 있는 방에 들어간 비율 | **< 50%** |
| 방당 평균 인원 | 활성 방 기준 | < 3 |
| 빈 방 생성률 | 전체 방 생성 중 혼자 방 | > 40% |

**첫 지표가 이 제품 전체에서 가장 중요한 숫자다.** 이게 50% 아래로 내려가면 다른 어떤 지표가 좋아도 제품은 죽고 있다.

## 5. 축 3 — 난입과 관전

가짜 참가자가 없으면 **"모일 때까지 기다리기"가 그대로 이탈**이 된다. 기다리는 시간을 없애야 한다.

### 5.1 대기 없는 입장

진행 중인 방에도 **언제나 들어갈 수 있다.** 들어온 사람은:

- 즉시 현재 라운드를 **관전**한다 (문제와 채팅이 보인다. 정답 판정만 안 된다)
- **다음 라운드부터 정식 참여** — 점수 0부터
- 최종 순위에는 참여한 라운드 수를 함께 표기한다

로비에서 3명을 기다리는 것보다, 2명이 시작한 판에 30초 뒤 합류하는 편이 훨씬 낫다. **화면에 사람이 움직이고 있으면 사람은 안 나간다.**

### 5.2 채팅은 즉시 열린다

관전 중에도 전체 채널 채팅은 친다. 판정만 안 될 뿐이다. 들어오자마자 말을 걸 수 있어야 소속감이 생긴다.

### 5.3 이탈 회수

- 판이 끝나면 **[한 판 더]** 로 같은 방에서 이어간다 — 방을 해체하지 않는다
- 사람이 빠져도 **2명만 남으면 계속 돌아간다**

---

## 6. 축 4 — 초대 우선

### 6.1 유입 단위가 다르다

혼자 검색해서 들어오는 사람 1명 vs 단톡방 링크로 들어오는 5명. **후자가 이 제품의 진짜 유입 단위다.** 8명 팀전은 사실상 이 경로 말고는 성립하지 않는다.

### 6.2 마찰 제거

```
링크 클릭 → 방 화면. 끝.
```

- 회원가입 없이 입장. 닉네임은 자동 생성, 그 자리에서 수정 가능
- 계정은 판이 끝난 뒤 "기록을 남기시겠어요?" 로 권한다
- 앱 설치 없음. 웹으로 끝난다

가입 화면을 한 번이라도 끼우면 단톡방 8명 중 3명이 사라진다.

### 6.3 공유 최적화

- 방 코드는 **6자리 대문자**. 헷갈리는 글자(I, O, 0, 1)는 뺀다
- 공유 카드에 **지금 몇 명 있는지** 실시간으로 박는다 — "5명이 기다리는 중"
- 결과 화면의 공유 이미지에 **같은 방 코드**를 넣어, 판이 끝난 뒤에도 그 방으로 돌아올 수 있게 한다

## 7. 축 5 — 혼자 모드

### 7.1 역할

혼자 모드는 **본진이 아니라 대기실**이다. 사람이 없는 순간에 나가지 않게 붙잡아 두는 것이 목적이다.

- 오늘의 문제 10개 (전원 동일 시드)
- 기록과 공유 카드
- 게임 규칙을 여기서 배운다 — 방에 들어가서 배우면 민폐가 된다

### 7.2 방으로 넘기는 다리

혼자 모드를 **끝낸 순간**이 가장 전환이 잘 되는 지점이다.

```
        오늘의 초성 퀴즈  8 / 10

    ─────────────────────────────
      지금 방에 12명이 있어요
      [ 바로 참가 ]
    ─────────────────────────────
```

- 인원수는 **실제 숫자**만 띄운다. 0명이면 다음 개장 시각을 띄운다
- 혼자 모드 중에도 방에 사람이 차면 상단에 얇은 띠로 알린다

### 7.3 단어 연상의 혼자 모드

단어 연상은 출제자가 필요해서 원래 혼자 못 한다. 그래서 혼자 모드에서는 **미리 만들어 둔 3단계 설명 스크립트**를 시간에 따라 흘리는 **연습 모드**로 제공한다 (04 문서 §5.5.3). 참가자 목록에 가짜 사람을 세우지 않는다 — 화면에 사람은 나 혼자고, 설명은 문제의 일부로 표시된다.

## 8. 단계별 종합 전략

### Phase 1 — 동접 0~50 (생존)

```
프라임타임    21:00~23:00 두 시간만
게임          초성 퀴즈 하나만
방            동시 1~2개로 강제. 사실상 [바로 참가] 만 노출
최소 인원     2명
난입          기본 켜짐
목표          "들어가면 누군가 있다" 를 100% 가깝게
```

이 단계에서 방 목록 UI는 아예 숨겨도 된다. 선택지를 주면 흩어진다.

### Phase 2 — 동접 50~300 (확장)

```
프라임타임    21:00~24:00 + 점심
게임          3종
방            동시 5~10개. 목록 공개, 사람 수 내림차순 고정
팀전          개방 (초대 방 우선)
목표          방당 평균 5명
```

### Phase 3 — 동접 300+ (정상화)

```
프라임타임    상시. 다만 랭크는 여전히 시간 제한
방            자유
랭크          매칭 큐 개방
목표          방당 평균 6명 이상 유지
```

## 9. 죽음의 나선 조기 경보

지표가 이 선을 넘으면 **즉시 Phase를 되돌린다.** 프라임타임을 다시 좁히고, 방 생성을 다시 막는다.

| 지표 | 위험선 | 의미 |
|---|---|---|
| **사람 있는 방을 본 비율** | **< 50%** | 가장 중요. 제품이 죽고 있다 |
| 방당 평균 인원 | < 3 | 흩어지고 있다 |
| 빈 방 생성률 | > 40% | 뭉치기 압력이 안 먹는다 |
| 입장 후 60초 내 이탈 | > 40% | 기다리다 나간다 — 난입을 더 열어야 한다 |
| 프라임타임 집중도 | < 50% | 시간이 안 모인다 |

## 10. 정직한 한계

- **뭉치기 압력에는 상한이 있다.** 동접이 정말 0이면 어떤 정렬 규칙도 사람을 만들어내지 못한다. 그 순간을 버티는 건 혼자 모드와 개장 예약뿐이다
- **가짜 참가자가 없다는 것은 초기에 더 아프다는 뜻이다.** 대신 "여기 봇밖에 없대"라는 말이 도는 경로가 원천적으로 없다. 초기 비용을 내고 신뢰를 사는 거래다
- **프라임타임 집중은 총 플레이 시간을 깎는다.** 낮에 오고 싶은 사람을 돌려보내는 비용을 감수하는 것이다. 동접이 충분해지기 전까지만 유효한 전략이고, 늦게까지 붙잡고 있으면 성장을 막는다
- **난입은 공정성을 깎는다.** 늦게 들어온 사람은 점수가 불리하다. 캐주얼에서는 감수하고, **랭크에서는 난입을 막는다**

## 11. 열려 있는 결정 사항

| # | 질문 | 메모 |
|---|---|---|
| S1 | 방 생성을 어디까지 막을 것인가 | 되묻기 한 번이 적정한지, 아예 막을지 |
| S2 | 난입 참가자의 순위 표기 | 참여 라운드 수 병기로 충분한가 |
| S3 | 프라임타임을 언제 푸는가 | 동접 몇 명부터 상시로 갈지 |
| S4 | 대기열 알림 채널 | 웹 푸시만으로 되는지, 탭 타이틀·소리도 쓸지 |
