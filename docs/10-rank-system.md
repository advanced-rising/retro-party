# 10. 랭크 시스템

> 랭크는 **두 종류**다. 싱글 기반(비동기)과 멀티 기반(동기).
> 전자는 사람이 없어도 돌아가고 후자는 동접이 필요하다 — 그래서 도입 시점이 다르다.

## 1. 두 갈래

| | 데일리 랭킹 | 티어 · 시즌 |
|---|---|---|
| 기반 | **싱글 데일리** | **멀티 랭크전** |
| 동기성 | 비동기 (하루 중 아무때나) | 동기 (동시 접속 필요) |
| 필요 인원 | **0명** | 4명+ |
| 경쟁 단위 | 그날의 점수 | 판별 승점 누적 |
| 리셋 | 매일 | 시즌 (3개월) |
| 도입 | **Phase 1** | Phase 3 |

**데일리 랭킹을 먼저 만든다.** 콜드스타트 시기에도 작동하는 유일한 경쟁 장치다.

---

## 2. 데일리 랭킹 (싱글 기반)

### 2.1 구조

```
매일 00:00 KST — 게임 3종 각각 오늘의 문제 확정 (전원 동일)
  ↓
유저가 하루 중 아무때나 1회 플레이
  ↓
점수 → 일간 리더보드
  ↓
다음날 00:00 리셋. 주간 누적은 별도 유지
```

### 2.2 게임별 데일리 규칙

| 게임 | 형태 | 점수 |
|---|---|---|
| **그 해** | 힌트 순차 공개, 6번 시도 | 적게 쓸수록 고득점 (1번 1000 → 6번 200) |
| **초성 퀴즈** | 60초 타임어택, 20문제 | 정답 수 × 속도 보너스 |
| **단어 연상** | AI 출제자와 1:1, 5단어 | 맞힌 수 × 남은 시간 |

**단어 연상 싱글은 AI 출제자로 성립한다.** 사전 생성된 설명 스크립트를 시간에 따라 흘린다 (04 문서 §5.5.3).

### 2.3 리더보드

```
┌──────────────────────────────┐
│  오늘의 랭킹 · 그 해          │
│  2026-08-06                  │
├──────────────────────────────┤
│  1위 야타족          1000  1번 │
│  2위 ㅋㅋ루삥뽕       800  2번 │
│  3위 감자탕러버       620  3번 │
│  ...                         │
│  ─────────────────────────   │
│  나  ⑫위  620  3번           │  ← 항상 내 순위를 보여준다
│  친구 중 2위                  │
└──────────────────────────────┘
```

| 범위 | 표시 |
|---|---|
| 전체 | 상위 100 + 내 순위 |
| 친구 | 팔로우한 사람만 (Phase 3) |
| 세대 | 연령대별 (선택 입력자만) |

**"친구 중 2위"가 전체 1000위보다 동기부여가 크다.** 작은 모수의 순위를 우선 보여준다.

### 2.4 게스트 처리

게스트도 플레이는 되지만 **랭킹에는 안 들어간다.** 결과 화면에서 유도한다.

```
당신의 점수 620점은 오늘 12위에 해당해요.
[ 기록 남기기 ]
```

**점수를 먼저 보여주고 가입을 권한다.** 순서가 반대면 안 한다.

## 3. 티어 · 시즌 (멀티 기반)

### 3.1 랭크전이란

캐주얼방과 분리된 **매칭 기반 경쟁 모드**.

| | 캐주얼방 | 랭크전 |
|---|---|---|
| 입장 | 방 목록 · 코드 · 빠른입장 | **매칭 큐** |
| 인원 | 2~8명 | **4명 고정** |
| 라운드 | 방장이 선택 | 10 고정 |
| 게임 | 방장이 선택 | **랜덤 또는 시즌 지정** |
| AI 참가자 | 있음 | **없음** ★ |
| 채팅 | 자유 | 이모트만 (08 문서) |
| 승점 | ✕ | ✅ |
| 중도 이탈 | 자유 | **패널티** |

**랭크전에 AI를 넣지 않는다.** 경쟁의 공정성이 흔들리면 랭크의 의미가 없다. 대신 4명이 안 모이면 매칭이 안 된다 — 그래서 동접이 필요하고 Phase 3인 것이다.

### 3.2 승점

```
4인 랭크전 1판 결과

1등  +30
2등  +12
3등   -4
4등  -12

이탈  -25 (판이 끝날 때까지 자리 지키면 최소한 -12)
```

**3·4등의 손실을 작게 잡는다.** 캐주얼 게임에서 크게 잃으면 그냥 안 한다. 올라가는 맛은 있되 떨어지는 고통은 약하게.

연승 보너스: 3연속 1~2등이면 +5.

### 3.3 티어

레트로 정체성을 티어에 심는다. 브론즈·실버·골드는 쓰지 않는다.

| 티어 | 승점 | 아이콘 (Phosphor) | |
|---|---|---|---|
| **초딩** | 0~299 | `backpack` | 시작 |
| **중딩** | 300~699 | `notebook` | |
| **고딩** | 700~1199 | `books` | |
| **대딩** | 1200~1799 | `guitar` | |
| **아재 / 이모** | 1800~2499 | `coffee` | 상위권 |
| **원로** | 2500+ | `crown` | 시즌 상위 1% |

티어 표시는 **아이콘 + 텍스트**다. 이모지는 쓰지 않는다 (06 문서 §4.2).

**"아재"가 최상위 직전이라는 게 이 게임에 딱 맞는다.** 나이를 자랑거리로 만든다.

- 티어 강등은 **한 단계까지만** (연속 강등 없음)
- 승격 시 이펙트 + 공유 카드
- 프로필·방 목록·게임방에 티어 뱃지 표시

### 3.4 시즌

| 항목 | 값 |
|---|---|
| 기간 | 3개월 |
| 리셋 | 승점의 **50%만 이월** (완전 리셋은 이탈 유발) |
| 보상 | 시즌 뱃지 (영구), 프로필 프레임, 아바타 |
| 명예의 전당 | 시즌별 상위 10명 영구 기록 |

**보상은 전부 장식이다.** 게임 성능에 영향을 주는 보상은 만들지 않는다.

### 3.5 매칭

```
매칭 큐 진입
  → 같은 티어 ±1 우선, 30초 대기
  → 안 되면 티어 범위 확대
  → 60초 초과: "지금은 사람이 적어요. 캐주얼방 어때요?" → 캐주얼로 유도
```

**매칭 실패를 막다른 길로 만들지 않는다.** 랭크전이 안 잡히면 캐주얼방으로 자연스럽게 넘긴다.

### 3.6 콜드스타트 대응

랭크전은 **4명 동시**가 필요해 콜드스타트에 가장 취약하다 (03 문서).

| 장치 | 내용 |
|---|---|
| **프라임타임 한정** | 초기엔 21:00~22:00에만 랭크 큐를 연다 |
| 티어 무시 매칭 | 동접이 적으면 티어 범위를 즉시 무제한으로 |
| 큐 인원 표시 | `지금 랭크 큐에 6명` — 기다릴 가치가 있는지 보여준다 |
| 캐주얼 유도 | 매칭 실패 시 (§3.5) |
| 도입 지연 | **동접 300 이상**일 때 정식 오픈 (07 문서 G3) |

**동접이 부족한데 랭크전을 열면 빈 큐만 보여주고 실망시킨다.** 차라리 늦게 여는 게 낫다.

## 4. 두 랭크의 관계

```
데일리 랭킹        →  가볍다. 매일 초기화. 누구나 참여
    ↓ 실력이 쌓이면
티어 · 시즌        →  무겁다. 3개월. 4명 매칭 필요
```

- 데일리 랭킹 상위권에게 **랭크전을 추천**한다
- 티어는 데일리 랭킹 화면에도 뱃지로 표시
- 승점은 **랭크전에서만** 오른다. 데일리는 별개 트랙

**두 트랙을 섞지 않는다.** 데일리 점수로 티어가 오르면 랭크전을 안 하게 된다.

## 5. 데이터

```sql
CREATE TABLE daily_puzzles (
  game_id   TEXT NOT NULL,
  date      DATE NOT NULL,
  seed      TEXT NOT NULL,
  payload   JSONB NOT NULL,          -- 정답 포함. 클라에 안 나감
  PRIMARY KEY (game_id, date)
);

CREATE TABLE daily_scores (
  game_id   TEXT NOT NULL,
  date      DATE NOT NULL,
  user_id   UUID NOT NULL,
  score     INTEGER NOT NULL,
  detail    JSONB,                   -- 시도 수, 정답 수 등
  played_at TIMESTAMPTZ,
  PRIMARY KEY (game_id, date, user_id)
);
CREATE INDEX ON daily_scores (game_id, date, score DESC);

CREATE TABLE rank_profiles (
  user_id     UUID PRIMARY KEY,
  season      TEXT NOT NULL,
  points      INTEGER DEFAULT 0,
  tier        TEXT,                  -- elementary|middle|high|college|ajae|elder
  peak_points INTEGER DEFAULT 0,
  wins        INTEGER DEFAULT 0,
  played      INTEGER DEFAULT 0,
  streak      SMALLINT DEFAULT 0
);

CREATE TABLE rank_matches (
  match_id    UUID PRIMARY KEY,      -- matches 테이블 참조 (05 문서)
  season      TEXT NOT NULL,
  game_id     TEXT NOT NULL,
  results     JSONB NOT NULL         -- [{user_id, rank, delta}]
);

CREATE TABLE season_hall (
  season      TEXT,
  rank        SMALLINT,
  user_id     UUID,
  points      INTEGER,
  PRIMARY KEY (season, rank)
);
```

실시간 순위는 **Durable Object**에서, 확정 순위만 PG에 스냅샷 (05 문서).

## 6. 안티치트

랭크가 생기는 순간 어뷰징이 온다.

| 위협 | 방어 |
|---|---|
| 데일리 재도전 | 계정당 1회. 서버가 `daily_scores` UNIQUE로 강제 |
| 다중 계정 | 계정 필수 + Turnstile. 완전 차단은 불가 — 이상 패턴 탐지 |
| 정답 유출 | 정답은 서버에만. 힌트는 시도할 때마다 하나씩 (05 문서 §9) |
| **승부 조작** | 랭크전은 **매칭으로만** 입장. 방 코드로 지인끼리 랭크전 불가 ★ |
| 이탈 반복 | 이탈 패널티 + 반복 시 큐 진입 제한 |
| 자동 봇 | 응답 시간 분포 이상 탐지 |

**★ 표시가 핵심이다.** 친구끼리 방을 만들어 점수를 몰아주는 걸 막으려면 **랭크전에 방 코드 입장을 아예 없애야 한다.**

### 6.1 팀 랭크를 당장 만들지 않는 이유

팀전(01 문서 §6.5)은 캐주얼방 옵션으로만 제공하고 **랭크전은 개인전 고정**이다.

팀 랭크는 승부 조작에 훨씬 취약하다 — 4명이 짜고 두 명씩 팀을 먹은 뒤 한쪽이 져주면 점수를 마음대로 옮길 수 있다. 이걸 막으려면 팀 자동 배정 + 팀 구성 이력 추적이 필요한데, 동접이 적은 시기엔 매칭 자체가 안 된다.

**Phase 4 이후, 동접이 충분해진 다음에 검토한다.**

## 7. 도입 시점

| Phase | 랭크 |
|---|---|
| **1** | 데일리 랭킹 (일간). 게임 3종 |
| **2** | 주간 랭킹, 친구 랭킹, 세대별 랭킹 |
| **3** | **랭크전 + 티어 + 시즌** (동접 300 이상일 때) |
| **4** | 시즌 보상 확대, 명예의 전당, 게임별 세부 티어 |

## 8. 열려 있는 결정 사항

| # | 항목 | 비고 |
|---|---|---|
| R1 | 티어 이름을 학력 계열로 갈 것인가 | 재밌지만 학력 소재가 불편할 수 있음 |
| R2 | 랭크전 인원 4명 고정이 맞는가 | 적을수록 매칭은 쉽지만 재미는 덜함 |
| R3 | 시즌 이월 50%가 적절한가 | 완전 리셋 vs 유지 사이 |
| R4 | 데일리와 티어를 완전히 분리하는 게 맞는가 | 통합하면 단순하지만 랭크전 유인이 줄어듦 |
| R5 | 랭크전에서 채팅을 막는 게 맞는가 | 경쟁 집중 vs 이 게임의 정체성 |
