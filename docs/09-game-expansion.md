# 09. 게임 확장

> 방 껍데기(01 문서)는 그대로 두고 게임만 갈아 끼운다.
> 이 문서는 **4번째 이후에 뭘 얹을지**와 **얹는 절차**를 다룬다.

## 1. 게임을 고르는 기준

| # | 기준 | 왜 |
|---|---|---|
| 1 | **채팅으로 답할 수 있는가** | 입력 UI를 새로 만들면 방 구조가 흔들린다 |
| 2 | **4~8명이 동시에 참여하는가** | 구경만 하는 사람이 생기면 방이 죽는다 |
| 3 | **라운드 20~90초** | 이 밖으로 나가면 다른 게임과 못 섞인다 |
| 4 | **콘텐츠를 조달할 수 있는가** | 저작권 걸리면 시작도 못 한다 |
| 5 | **기존 게임과 리듬이 다른가** | 비슷한 게 둘이면 하나만 못하다 |
| 6 | **최소 인원이 낮은가** | 3명 넘게 필요하면 콜드스타트에 취약 (03 문서) |

**5번이 특히 중요하다.** 현재 셋은 전부 "문제 보고 채팅으로 외치기"다. 다음은 **입력 방식이나 턴 구조가 다른 것**이어야 한다.

## 2. 현재 라인업과 빈 자리

| # | 게임 | 형태 | 라운드 | 최소 |
|---|---|---|---|---|
| 1 | 초성 퀴즈 | 동시 · 채팅 | 20초 | 2 |
| 2 | 단어 연상 | 출제자 · 채팅 | 90초 | 3 |
| 3 | 그 해 | 동시 · 채팅 | 60초 | 2 |

**빈 자리: 턴제 · 비채팅 입력 · 소셜 추리.**

## 3. 후보

### #4 끝말잇기 (쿵쿵따) ⭐ 1순위

```
┌──────────────────────────────┐
│  🕶 야타족 차례       ⏱ 6초   │
│                              │
│      오 락 실                 │
│           ↓                  │
│      실 _ _                  │
│                              │
│  🥔 감자탕러버  실내화        │
│  🌀 ㅋㅋ루삥뽕  실뜨기        │
└──────────────────────────────┘
```

세 글자 단어로 끝말을 잇는다. 시간 내 못 대면 탈락, 마지막 1인이 승.

| 기준 | 평가 |
|---|---|
| 채팅 입력 | ✅ |
| 동시 참여 | 🟡 턴제라 대기 시간 — 대신 **긴장감이 다르다** |
| 라운드 | 판당 3~6분 |
| 콘텐츠 | ✅ 표준국어대사전 등 **사전 데이터** |
| 리듬 차별 | ✅ **유일한 턴제** |
| 최소 인원 | 2 |

**왜 1순위인가**: 원조 향수(쿵쿵따)이고, 턴제라 리듬이 완전히 다르며, 콘텐츠가 사전 하나로 끝난다.

**난점**: 사전 데이터 확보와 판정 규칙(두음법칙, 한방단어 처리)이 생각보다 까다롭다. 그리고 **웹 끝말잇기는 이미 여럿 있다** — 차별점은 방·채팅·향수 소재뿐이다.

### #5 그때 그 값 (가격 맞추기)

```
        1994년
     새우깡 한 봉지

   ├────────●────────┤
   100원          2,000원

      오차 8%   +80점
```

연도와 물건을 주고 가격을 맞힌다. 슬라이더 입력, 오차율로 채점.

| 기준 | 평가 |
|---|---|
| 채팅 입력 | ✕ **슬라이더** — 그래서 오히려 리듬이 다름 |
| 동시 참여 | ✅ 전원 동시 제출 |
| 라운드 | 20초 |
| 콘텐츠 | ✅ **「그 해」 데이터 재활용** (04 문서 price 카테고리) |
| 리듬 차별 | ✅ 유일한 비채팅 입력 |
| 최소 인원 | 2 |

**가장 싸게 만들 수 있는 게임.** 콘텐츠가 이미 있고 구현이 단순하다.
**단점**: 채팅이 줄어 플랫폼 정체성과 약간 어긋난다. 정답 공개 후 반응 채팅으로 보완한다.

### #6 스무고개

출제자가 단어를 고르고, 나머지가 채팅으로 예/아니오 질문을 던진다. 출제자는 `[예] [아니오] [부분적으로]` 버튼으로만 답한다. 20질문 안에 맞히면 승.

| 기준 | 평가 |
|---|---|
| 채팅 입력 | ✅ 질문도 정답도 채팅 |
| 동시 참여 | ✅ 누구나 질문 가능 |
| 콘텐츠 | ✅ **단어 목록만.** 단어 연상과 공유 |
| 리듬 차별 | 🟡 단어 연상과 구조가 비슷 (출제자형) |
| 최소 인원 | 3 |

**장점**: 콘텐츠 비용 0, 구현 단순, 대화량 최대.
**단점**: 단어 연상과 겹친다. 둘 다 넣으면 하나는 안 하게 될 수 있다.

---

### #7 캐치마인드 (그림)

원조. 한 명이 그리고 나머지가 채팅으로 맞힌다.

| 기준 | 평가 |
|---|---|
| 채팅 입력 | ✅ |
| 리듬 차별 | ✅ 유일한 그리기 |
| 콘텐츠 | ✅ 단어 목록만 |
| **구현** | 🔴 **캔버스 실시간 동기화** — 지금까지 중 가장 무겁다 |
| 파급력 | 🟢 **가장 큼.** 그림이 웃기면 그대로 밈이 된다 |

**언젠가는 만들어야 할 게임.** 다만 구현 비용이 다른 것의 3~4배다 — 스트로크 동기화, 지연 보정, 되돌리기, 모바일 터치 드로잉.

**Phase 3 이후로 미룬다.** 단어 연상이 이 자리를 임시로 메우고 있다.

### #8 맞춤법 배틀

60초에 문제 25개, 동시에 풀고 점수 경쟁.

| 기준 | 평가 |
|---|---|
| 채팅 입력 | ✕ 선택지 클릭 |
| 리듬 차별 | ✅ 순수 속도전 |
| 콘텐츠 | 🟡 문제 800개 자체 제작 |
| 리스크 | 애매한 문제 하나가 커뮤니티에서 물어뜯긴다 |

무난하지만 특별하지 않다. 우선순위 낮음.

## 4. 만들지 않을 것

| 후보 | 왜 |
|---|---|
| 노래 이어부르기 · 인트로 맞히기 | **음원 저작권**. 불가 |
| 옛날 사진 · 광고 영상 퀴즈 | 이미지·영상 저작권. 불가 |
| 인물 사진 맞히기 | 초상권 |
| 마피아 · 라이어게임 | **최소 6명** 필요 → 콜드스타트에 치명적 |
| 실시간 액션 게임 | 지연 요구가 완전히 다름. DO 구조에 부적합 |

**저작권이 걸리는 소재는 처음부터 제외한다.** 이 프로젝트가 텍스트 중심인 이유다.

## 5. 추천 순서

```
#4  끝말잇기      턴제 — 리듬 차별이 가장 큼        Phase 2
#5  그때 그 값    콘텐츠 재활용 — 가장 저렴          Phase 2~3
#6  스무고개      콘텐츠 0 — 대화량 최대            Phase 3
#7  캐치마인드    구현 무거움 — 파급력 최대          Phase 3~4
```

**게임 6개가 상한선이다.** 그 이상이면 방 목록에서 뭘 할지 못 고르고, 각 게임의 동접이 흩어져 **콜드스타트가 다시 온다** (03 문서 §7).

6개를 채우면 새 게임 대신 **기존 게임의 모드·소재 확장**으로 간다.

## 6. 새 게임 추가 절차

### 6.1 파일

```
packages/games/{gameId}/
├─ index.ts        RoomGame 구현 (createRound / judge / reveal / viewFor)
├─ Board.tsx       문제 영역 컴포넌트
├─ ai.ts           AI 참가자 행동 계획
└─ schema.ts       문제 타입

apps/web/lib/registry.ts    한 줄 추가
```

DB 마이그레이션 **없음** — 게임별 데이터는 `match_players` 집계와 KV 문제 세트로 처리한다.

### 6.2 자동으로 붙는 것

- 방 목록 · 대기실 · 게임 선택
- 채팅 · 이모트 · 필터
- 타이머 · 라운드 진행 · 점수판
- 결과 화면 · 하이라이트 · 공유 카드
- 재접속 · 관전
- AI 참가자 투입 (행동 계획만 게임별로 작성)

### 6.3 체크리스트

- [ ] §1의 6개 기준을 통과하는가
- [ ] `viewFor`가 정답을 누출하지 않는가 (**테스트 필수**, 05 문서 §9)
- [ ] `Date.now()` / `Math.random()`을 쓰지 않는가
- [ ] 콘텐츠 라이선스가 깨끗한가
- [ ] 기존 게임과 리듬이 다른가
- [ ] 최소 인원이 3 이하인가
- [ ] AI 참가자 행동 계획이 구현됐는가
- [ ] 초기 콘텐츠 물량 + 보강 계획이 있는가

### 6.4 목표

**4번째 게임 구현에 3주 이내.** 넘어가면 `room-kit` 인터페이스가 잘못된 것이다.

## 7. 게임 간 시너지

| 장치 | 내용 |
|---|---|
| **한 방에서 게임 교체** | 방장이 다음 판 게임을 바꾼다. 리듬이 달라 물리지 않는다 |
| **결과 화면 제안** | `다음 판은 끝말잇기 어때요?` |
| **콘텐츠 공유** | 단어 목록을 초성·연상·스무고개가 공유. 「그 해」 데이터를 가격 맞추기가 재활용 |
| **통합 전적** | 게임별 승률 + 전체. `초성 장인`, `연상왕` 같은 칭호 |
| **믹스 모드** | 라운드마다 게임이 바뀐다 (Phase 3) |

**콘텐츠 공유가 가장 실질적이다.** 단어 하나를 넣으면 세 게임에서 쓰인다 (04 문서).

## 8. 열려 있는 결정 사항

| # | 항목 | 비고 |
|---|---|---|
| E1 | 4번째를 끝말잇기 vs 그때 그 값 | 차별성 vs 개발 비용 |
| E2 | 스무고개가 단어 연상과 중복인가 | 둘 다 넣으면 하나는 죽을 수 있음 |
| E3 | 캐치마인드를 언제 만들 것인가 | 파급력 최대, 비용도 최대 |
| E4 | 게임 상한 6개가 맞는가 | 동접 분산 vs 다양성 |
| E5 | 믹스 모드가 혼란스럽지 않을까 | 신선함 vs 학습 부담 |
