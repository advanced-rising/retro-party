# 05. 로드맵

> 원칙: **콘텐츠가 병목이다.** 코드는 몇 주면 되지만 4,000건의 검증된 힌트는 그렇지 않다.
> 그래서 파이프라인을 가장 먼저, 게임보다 먼저 만든다.

## Phase 0 — 콘텐츠 검증 (2주)

**질문: 이 방식으로 믿을 만한 힌트가 나오는가?**

게임은 아직 안 만든다. 코드도 대부분 버릴 스크립트다.

### 범위

| 항목 | 내용 |
|---|---|
| 대상 | 5개 연도 × 5개 카테고리 = 25셀만 |
| 생성 | **Claude Code로 직접** (02 문서 §3.0). API 파이프라인 안 만듦 |
| 산출물 규약 | `CONTENT-RULES.md` + `data/facts/*.json` 스키마 확정 |
| 검증 | `verify-tier-a.mjs` (공공 API 대조, LLM 불필요) + Tier B 별도 세션 |
| 산출 | 힌트 후보 ~300건 + 전수 사람 검수 |
| 게임 | 없음. 텍스트로 5판 손으로 플레이해봄 |
| **API 비용** | **$0** |

여기서 만드는 `CONTENT-RULES.md`와 JSON 스키마가 자산이다. 나중에 API로 전환하면 그대로 시스템 프롬프트와 구조화 출력 스키마가 된다.

### 관문 G0

| 조건 | 기준 |
|---|---|
| **G0-A. 사실 정확도** | 300건 전수 검수, **연도 오류 < 1%** |
| **G0-B. 재미** | 손으로 만든 5판을 10명에게 시켜서 "재밌다" 7명 이상 |
| **G0-C. 난이도** | 6번 안에 맞히는 비율 70~90% 사이 |

**G0-A를 못 넘기면 전부 중단이다.** 검증 방식을 다시 설계한다.
G0-C가 90%를 넘으면 너무 쉽고, 70% 미만이면 힌트 티어 배분이 잘못됐다.

**병행**: 공공 API 3종(KOSIS·ECOS·최저임금) 접근 확보 및 스키마 파악. 여기서 막히면 Tier A가 통째로 무너진다.

## Phase 1 — MVP (6주)

**질문: 사람들이 오고, 내일 또 오는가?**

### 범위

| 포함 | 제외 |
|---|---|
| 「그 해」 데일리 + 무한 | 시대 팩, 스피드런, 대결 |
| **힌트 1,500건** (25~30개 연도 × 60) | 전 연도 커버 |
| 「그 해」 요약 카드 | 다른 해 넘겨보기 |
| 텍스트 공유 카드 | 이미지 공유 카드 |
| PC통신 셸 + 일간 랭킹 | 계정 (게스트만) |
| 게임 모듈 인터페이스 | 두 번째 게임 |
| Cloudflare Workers + DO + PG | **NestJS** — 아직 필요 없음 (03 문서 §2.1) |
| 콘텐츠: Claude Code + 스크립트 3개 | API 파이프라인 |

**힌트 1,500건이면 25연도 순환 = 25일 주기.** MVP 검증 기간으로는 충분하다.
인프라는 **Workers + Durable Objects + PostgreSQL**로 완결된다 (NestJS 미도입).

### 주차별

| 주 | 콘텐츠 (Claude Code) | 코드 |
|---|---|---|
| W1 | 250셀 착수 — 매일 30~40셀 | `packages/game-kit` 인터페이스 확정 |
| W2 | 계속 | platform-api Worker, PG 스키마, 데일리 Cron |
| W3 | 계속 (~150셀 누적) | PC통신 셸 UI, 「그 해」 게임 화면 |
| W4 | 계속 (~250셀 완료) | 힌트 공개 연출, 「그 해」 요약 카드 |
| W5 | Tier A 자동 검증 + Tier B 교차검증 | 공유, 스트릭, 일간 랭킹 |
| W6 | 사람 검수 마무리 | 온보딩, 소프트 런칭 |

**콘텐츠와 코드를 병렬로 굴린다.** 콘텐츠는 하루 1~2시간씩 나눠 하고 나머지 시간에 코드를 쓴다. 한 번에 몰아서 하면 구독 사용량 한도에 걸린다.

### 성공 판정 (런칭 후 2주)

| 지표 | 목표 |
|---|---|
| 방문자 | 8,000 |
| 첫 판 완주율 | 75% |
| **D1 리텐션** | **30%** ← 데일리 게임의 생명 |
| D7 리텐션 | 15% |
| 공유율 | 12% |
| 힌트 오류 신고 | 100건당 1건 미만 |

**D1이 30% 미만이면 확장하지 않는다.** 「그 해」 카드와 난이도를 먼저 고친다.

### 마케팅 (돈 안 쓰는 것만)

- 접속 화면 스크린샷 1장 + "1997년 자장면이 얼마였게요?"
- 커뮤니티: 디시 · 에펨 · 클리앙 · 뽐뿌 · X/스레드
- **물가 충격이 훅이다.** 게임 설명보다 힌트 한 줄을 먼저 보여준다
- 데일리 공유 카드가 자연 확산의 주 채널

## Phase 2 — 두 번째 게임 (8주)

**질문: 플랫폼 구조가 실제로 작동하는가?**

여기서 게임 모듈 인터페이스가 시험대에 오른다. 두 번째 게임을 얹는 데 고생하면 설계가 틀린 것이다.

| 항목 | 내용 |
|---|---|
| **「맞춤법 지옥」 추가** | 07 문서. 60초 아케이드형 — 「그 해」와 완전히 다른 형태 |
| 계정 | 카카오/구글, 게스트 기록 연결 |
| 힌트 확장 | **4,000건 전량**, 전 연도 커버 |
| ↳ 생성 방식 판단 | Claude Code 계속 vs API 전환 (02 문서 §6). 판단 기준: 남은 물량 처리 시간이 $140보다 아까운가 |
| **NestJS 도입** | 관리자 UI, 오류 신고 처리, 난이도 보정 배치 |
| **멀티플레이 인터페이스 확정** | `MultiplayerSpec` **정의만**, 구현 없음. 지금 안 넣으면 Phase 3에 게임을 전부 갈아엎어야 함 (08 문서 §4) |
| 「그 해」 확장 | 시대 팩, 스피드런 60, 주간 챌린지 |
| 다른 해 넘겨보기 | 전 연도 아카이브 |
| 세대 비교 | 연령대 선택 + 세대별 통계 |
| 이미지 공유 카드 | R2 + Satori |
| 통합 랭킹 | 게임별 + 전체 |
| 난이도 자가보정 | 배치 가동 |

### 성공 판정

| 지표 | 목표 |
|---|---|
| MAU | 60,000 |
| DAU/MAU | 25% |
| D7 리텐션 | 22% |
| 스트릭 7일+ | 15% |
| **두 게임 모두 플레이하는 비율** | **35%** ← 플랫폼 가설 검증 |
| 두 번째 게임 구현 소요 | **3주 이내** ← 모듈 구조 검증 |

마지막 두 줄이 이 Phase의 진짜 목표다.

## 인력

| 역할 | Phase 0~1 | Phase 2~3 |
|---|---|---|
| 풀스택 개발 | 1 (겸 기획) | 2 |
| 콘텐츠 검수 | 0.3 (겸임) | 1 (전담) |
| 디자이너 | 0 (직접) | 0.5 (외주) |

**Phase 2부터 콘텐츠 검수 전담이 필요하다.** 4,000건을 사람이 봐야 하고, 이후에도 오류 신고와 정기 보강이 계속된다. 이게 이 제품의 유일한 지속적 인건비다.

개발은 1인으로 Phase 2까지 갈 수 있다. 게임 모듈 구조가 제대로 서면 게임 하나 추가가 2~3주다.

## 비용 추정 (월)

| 항목 | Phase 1 | Phase 2 | Phase 3 |
|---|---|---|---|
| Cloudflare Workers Paid | $5 | $5 | $5 |
| Workers 초과 사용 | $0 | ~$10 | ~$35 |
| Durable Objects | $0 | ~$8 | ~$25 |
| KV / R2 / Queues | ~$1 | ~$4 | ~$15 |
| PostgreSQL (Neon) | $0 (Free) | $19 | $69 |
| NestJS 호스팅 | **$0** (미도입) | ~$10 | ~$20 |
| **Claude API (콘텐츠)** | **$0** | $0 ~ $12 | $0 ~ $15 |
| 도메인 | $2 | $2 | $2 |
| Sentry | $0 | $0 | $26 |
| **합계** | **~$8** | **~$58** | **~$197** |

콘텐츠는 Claude Code로 만들므로 **Phase 1 인프라 비용이 월 $8**이다. Phase 2에서 API 전환을 택하면 1회성 ~$140 + 월 ~$12가 추가된다 (02 문서 §6).

**런타임에 LLM을 호출하지 않으므로 유저가 늘어도 이 비용은 거의 안 는다.** 이 구조의 핵심 이점이다.

## 위험 관문 (Gate)

| 관문 | 조건 | 미통과 시 |
|---|---|---|
| **G0-A** | 연도 오류율 < 1% (300건 전수 검수) | 검증 방식 재설계. 여기서 막히면 전부 중단 |
| **G0-B** | 재미 7/10 | 게임 규칙 재설계 (시도 횟수, 온도 피드백) |
| **G0-C** | 6번 내 정답률 70~90% | 힌트 티어 배분 재조정 |
| G0-D | 공공 API 3종 접근 확보 | Tier A 대체 검증 방식 필요 |
| G1 | D1 리텐션 30% | 「그 해」 카드·난이도 재작업, 확장 보류 |
| G2 | 두 번째 게임 3주 내 구현 | 모듈 인터페이스 재설계 |
| G2 | 두 게임 모두 플레이 35% | 플랫폼 가설 재검토 — 단일 게임에 집중 |
| G3 | MAU 60k, D7 22% | 수익화 보류 |

**G0-A와 G2가 이 프로젝트의 두 갈림길이다.**
전자는 "콘텐츠를 믿을 수 있는가", 후자는 "플랫폼이 성립하는가"를 묻는다.
