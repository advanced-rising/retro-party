# 01. 코어 루프 — 방 구조

> 게임이 뭐든 이 껍데기는 같다. 방 목록 → 대기실 → 라운드 반복 → 결과 → 대기실.
> **한 번 들어오면 30분 있게 만드는 것**이 이 구조의 목적이다.

## 1. 전체 흐름

```
      접속
       ↓
  ┌─ 방 목록 ────────────────────────┐
  │  · 공개방 리스트 (인원/게임/상태) │
  │  · 빠른 입장                      │
  │  · 방 만들기                      │
  │  · 코드로 입장                    │
  └───────────┬──────────────────────┘
              ↓ 입장
  ┌─ 대기실 ─────────────────────────┐
  │  참가자 아바타 · 채팅 · 게임 선택 │◀────────┐
  │  방장이 [시작]                    │         │
  └───────────┬──────────────────────┘         │
              ↓                                 │
  ┌─ 라운드 (× 10) ──────────────────┐         │
  │  문제 → 채팅으로 정답 → 채점      │         │
  │  → 정답 공개 → 다음 라운드        │         │
  └───────────┬──────────────────────┘         │
              ↓                                 │
  ┌─ 결과 ───────────────────────────┐         │
  │  최종 순위 · 하이라이트 · 공유    │─────────┘
  │  [한 판 더]  [방 나가기]          │  대기실 복귀
  └──────────────────────────────────┘
```

**결과 화면에서 방을 나가지 않고 대기실로 돌아가는 것**이 핵심이다. 이탈 지점을 만들지 않는다.

## 1.5 세 가지 모드

같은 게임을 세 가지 방식으로 즐긴다. **콘텐츠와 게임 로직은 공유하고 껍데기만 다르다.**

```
싱글                     멀티                          랭크
──────────────────      ──────────────────────       ──────────────────
🎯 데일리  하루 1회      🎪 캐주얼방  개인전            📊 데일리 랭킹
   전원 동일 문제           방 만들기 · 코드 · 빠른입장      싱글 기반 · 비동기
   ★ 랭킹 집계                                            Phase 1부터
                        🤝 팀전      2v2 · 3v3 · 4v4
🔁 연습    무한             팀 채팅 분리 · 점수 합산      🏆 티어 · 시즌
   기록 없음                                                멀티 기반 · 동기
                        ⚔️ 랭크전    매칭 · 승점            Phase 3부터
```

| 모드 | 사람 필요 | 세션 | 역할 |
|---|---|---|---|
| **싱글 · 데일리** | 0명 | 2~3분 | 유입 · 매일 복귀 · **콜드스타트 완충** |
| **싱글 · 연습** | 0명 | 무제한 | 실력 쌓기 · 심심풀이 |
| **멀티 · 캐주얼** | 2~3명 | 10~30분 | **재미의 본체** |
| **멀티 · 팀전** | 4명 (2v2) | 10~20분 | 협력 · **실력 편차 완화** |
| **멀티 · 랭크전** | 4명 | 10~15분 | 경쟁 · 장기 목표 |

### 왜 셋 다 필요한가

- **싱글이 없으면** 새벽 3시에 온 사람이 빈 방을 보고 영영 떠난다 (03 문서)
- **멀티가 없으면** 그냥 또 하나의 퀴즈 앱이다
- **랭크가 없으면** 한 달 하고 질린다. 장기 목표가 있어야 남는다

**개발 우선순위는 멀티 > 싱글 > 랭크**지만, 셋 다 없으면 제품이 불완전하다.

상세: 랭크는 10 문서, 게임별 싱글 규칙은 02 문서.

## 2. 방

### 2.1 규격

| 항목 | 값 |
|---|---|
| 인원 | 2~8명 (게임별 최소 인원 다름) |
| 라운드 | 10회 (방장이 5/10/15 선택) |
| 한 판 | 8~12분 |
| 공개/비밀 | 공개방은 목록에 노출, 비밀방은 6자리 코드 |
| 방장 | 최초 입장자. 나가면 다음 사람에게 승계 |
| 관전 | 정원 초과 시 관전 입장 가능 (채팅 참여 O, 점수 X) |

### 2.2 방장 권한

- 게임 선택 · 라운드 수 · 난이도
- 시작 / 강제 다음 라운드
- 강퇴 (같은 사람 재입장 차단 10분)

**강퇴는 반드시 있어야 한다.** 채팅이 있는 방에서 진상 한 명이 방을 통째로 죽인다.

### 2.3 방 목록

```
┌──────────────────────────────────────────┐
│  🔍 [빠른 입장]        [+ 방 만들기]      │
├──────────────────────────────────────────┤
│  3번방  그 해        ●●●●●○○○  5/8  진행중│
│  7번방  단어 연상    ●●●○○○○○  3/8  대기 │
│  1번방  초성 퀴즈    ●●●●●●●○  7/8  진행중│
│  12번방 그 해        ●●○○○○○○  2/8  대기 │
├──────────────────────────────────────────┤
│  코드로 입장  [ _ _ _ _ _ _ ]             │
└──────────────────────────────────────────┘
```

정렬: **입장 가능한 방을 위로**. 꽉 찬 방과 빈 방은 아래로.
`빠른 입장`은 인원이 가장 많으면서 자리가 남은 방으로 넣는다 — **사람을 뭉치게 하는 게 항상 우선이다** (03 문서).

## 3. 대기실

```
┌──────────────────────────────────────────┐
│  3번 방                          🔗 코드  │
├──────────────────────────────────────────┤
│  🕶 야타족 (방장)   🥔 감자탕러버         │
│  🌀 ㅋㅋ루삥뽕      🤖 96학번 (AI)        │
│  ➕ 빈 자리 ×4                            │
├──────────────────────────────────────────┤
│  게임   [ 그 해 ▾ ]   라운드 [ 10 ▾ ]     │
├──────────────────────────────────────────┤
│  🥔 감자탕러버  ㅎㅇ                      │
│  🌀 ㅋㅋ루삥뽕  단어연상 하자             │
│  [ 메시지 입력                      ]     │
├──────────────────────────────────────────┤
│              [  시  작  ]                 │
└──────────────────────────────────────────┘
```

- **대기실에서도 채팅이 돈다.** 여기서 이미 재미가 시작된다
- AI 참가자는 `🤖` 로 명확히 표시 (03 문서)
- 방장이 아니면 [시작] 대신 `방장이 시작하기를 기다리는 중…`
- 2명 미만이면 시작 불가 — 대신 **AI를 채워 넣을 수 있다**

## 4. 라운드

### 4.1 공통 페이즈

게임이 달라도 라운드 구조는 같다.

```
① 준비    1.5s   "라운드 4"  전체 화면 카운트
② 출제    ~3s    문제 등장 (게임별)
③ 진행    15~90s 채팅으로 정답. 타이머 진행 바
④ 정산    3~5s   정답 공개 + 점수 변동 애니메이션
                 (그 해 → 「그 해」 카드, 단어연상 → 출제자 코멘트)
⑤ 다음    0.5s   전환
```

**③ 진행 중에도 채팅이 계속 흐른다.** 정답이 아닌 잡담도 그대로 나온다. 그게 이 게임이다.

### 4.2 정답 판정

| 항목 | 규칙 |
|---|---|
| 입력 | 채팅창. 별도 정답 입력 UI 없음 |
| 판정 | 서버(DO)가 정규화 후 비교 (공백·자모·대소문자 무시) |
| 정답 시 | 해당 메시지가 **정답 스타일로 강조**되고 점수 부여 |
| 오답 시 | 그냥 일반 채팅으로 남는다 (틀린 걸 지우지 않는다 — 그게 재밌다) |
| 근접 | 게임별. 「그 해」는 ±1년에 부분점수 |
| 중복 정답 | 먼저 맞힌 순서대로 차등 점수 |

**오답을 숨기지 않는 게 중요하다.** "1996?" "아니야" "1998!" 하는 과정이 채팅의 재미다.

### 4.3 점수

```
정답 순위    1등 100   2등 70   3등 50   4등~ 30
속도 보너스  문제 공개 후 5초 이내 ×1.5
난이도 보정  힌트가 적게 열렸을 때 맞히면 ×1.3
```

**꼴찌도 30점은 받는다.** 0점이 반복되면 나간다. 격차는 벌리되 바닥은 만들지 않는다.

### 4.4 타이머

상단 진행 바가 줄어든다. 색이 변한다:
`라임(여유) → 앰버(15%) → 레드(5%)`

마지막 5초는 숫자가 커지고 살짝 진동한다. **조급함이 이 게임의 엔진이다.**

## 5. 결과

```
┌──────────────────────────────────────────┐
│              게임 종료                    │
├──────────────────────────────────────────┤
│  🥇 🕶 야타족          840                │
│  🥈 🌀 ㅋㅋ루삥뽕      620                │
│  🥉 🥔 감자탕러버      450                │
│     🤖 96학번          310                │
├──────────────────────────────────────────┤
│  ⚡ 가장 빠른 정답   야타족  3.2초        │
│  🔥 최다 연속       ㅋㅋ루삥뽕  4연속     │
│  💬 최다 채팅       감자탕러버  47개      │
├──────────────────────────────────────────┤
│    [ 한 판 더 ]         [ 나가기 ]        │
│              결과 공유 →                  │
└──────────────────────────────────────────┘
```

### 하이라이트가 순위보다 중요하다

1등만 기분 좋은 화면이면 나머지 3~7명이 나간다. **각자 뭐라도 하나 가져가게 만든다.**

수여 가능한 배지 (해당자에게만):
`가장 빠른 정답` `최다 연속` `최다 채팅` `역전왕` `아깝다(2등 다수)` `첫 정답` `끝까지 포기 안 함`

### [한 판 더]

- 10초 카운트다운 후 자동으로 대기실 복귀
- **아무도 안 누르면 그냥 대기실로 간다.** 방을 해체하지 않는다
- 절반 이상이 누르면 즉시 시작

## 6. 채팅

**채팅은 이 게임의 입력 장치이자 재미 그 자체다.**

| 항목 | 규칙 |
|---|---|
| 위치 | 화면 하단 고정. 모바일에서 키보드 올라와도 가려지지 않게 |
| 형태 | 말풍선 아님. **라인형** (닉네임 + 메시지) — 정보 밀도 우선 |
| 정답 | 라임 배경 + `✓ +100` 뱃지로 강조 |
| 저장 | **하지 않는다.** 릴레이만 (08 문서) |
| 필터 | 실시간 금칙어 + 도배 제한 |
| 랜덤방 | 자유 채팅. 단, 모르는 사람 방이므로 신고 버튼 상시 노출 |

### 이모트

타이핑이 느린 사람 · 모바일 사용자를 위한 빠른 반응. 하단 버튼 6개.

```
👏 잘한다   😱 헐   😂 ㅋㅋㅋ   😭 아깝다   🤔 음…   👋 안녕
```

한 번 누르면 채팅에 흐른다. 연타 방지 3초 쿨다운.

## 6.5 팀전

방 설정의 **옵션**이다. 별도 모드가 아니라 방장이 켜면 팀이 갈린다.

| 항목 | 값 |
|---|---|
| 편성 | 2v2 · 3v3 · 4v4 (짝수 인원) |
| 팀 구성 | 자동 배정 / 방장 배정 / 자유 선택 |
| 점수 | **팀원 점수 합산** |
| 홀수 인원 | AI 참가자로 채우거나 관전 대기 |
| 팀 이름 | 🔴 청팀 / 🔵 홍팀 (색 고정) |

### 6.5.1 ★ 팀 채팅 분리 — 팀전의 핵심 설계

**채팅이 곧 정답 입력인 게임에서, 전체 채팅에 답을 치면 상대 팀이 그대로 본다.** 팀전이 성립하려면 채널이 갈려야 한다.

```
┌──────────────────────────────┐
│  🔴 우리팀        🔵 전체     │  ← 탭 전환
├──────────────────────────────┤
│  🥔 감자탕러버  1996인가?     │
│  🕶 야타족     아냐 IMF면 97  │
│  🥔 감자탕러버  아 맞다        │
│  🕶 야타족     1997   ✓ +100 │
├──────────────────────────────┤
│  [ 우리팀에게 말하기      ]   │  ← 기본이 팀 채널
└──────────────────────────────┘
```

| 채널 | 보이는 범위 | 정답 판정 | 기본값 |
|---|---|---|---|
| **팀 채팅** | 같은 팀만 | ✅ 여기서만 | **기본** |
| 전체 채팅 | 모두 | ✕ 판정 안 함 | 도발·인사용 |

**정답은 팀 채널에서만 판정한다.** 전체 채널에 답을 쳐도 점수가 안 들어간다 — 실수로 흘려도 손해만 본다.

전체 채널은 **정산 직후에 열린다.** "아 그거였어?" 하는 반응이 양 팀 사이에 오가야 재밌다.

### 6.5.2 왜 팀전인가

| 이점 | |
|---|---|
| **실력 편차를 덮는다** | 혼자 못 맞혀도 팀에 묻어간다. 개인전에서 계속 꼴찌면 나가지만 팀전은 버틴다 |
| **채팅량이 폭증한다** | 상의하느라 말이 많아진다. 이 게임의 정체성과 정확히 맞물린다 |
| **지인 유입에 강하다** | "우리 편 해" 가 초대 문구가 된다 (03 문서 §6) |
| **역전 서사** | 팀 합산이라 마지막 라운드까지 결과를 모른다 |

### 6.5.3 게임별 팀전

| 게임 | 방식 |
|---|---|
| **초성 퀴즈** | 팀 채팅으로 상의하며 맞히기. 먼저 맞힌 팀이 고득점 |
| **그 해** | 같음. 힌트가 열릴 때마다 팀 채팅이 시끄러워진다 |
| **단어 연상** ★ | **팀마다 자기 출제자를 둔다.** 양 팀이 동시에 다른 단어로 진행, 먼저 맞힌 팀 승 |

**단어 연상 팀전이 가장 재밌을 가능성이 높다.** 캐치마인드 팀전과 같은 구조인데, 우리 팀 출제자의 설명이 얼마나 답답한지가 그대로 웃음이 된다.

### 6.5.4 랭크전과의 관계

**랭크전은 개인전 고정이다.** 팀 랭크는 승부 조작(지인끼리 팀 먹고 몰아주기)에 취약해서 Phase 4 이후로 미룬다 (10 문서 §6).

## 7. 접속 · 재접속

모바일에서 앱을 잠깐 나가는 건 흔하다. 이걸 이탈로 처리하면 안 된다.

```
연결 끊김
  → 아바타에 흐림 처리 + "연결 중…" 표시
  → 방은 그대로 진행 (이 사람만 점수를 못 딴다)
  → 60초 내 재접속: 현재 상태 전체 재전송, 그대로 복귀
  → 60초 초과: 방에서 제거 (관전자로 강등)
```

**끊긴 사람 때문에 방이 멈추면 안 된다.** 게임은 계속 돈다.

## 8. 게스트

**방에 들어가는 데 가입이 필요하면 무리 유입이 죽는다.** 단톡방에서 코드 받고 들어오는 사람이 회원가입 화면을 보면 절반이 나간다.

| | 게스트 | 계정 |
|---|---|---|
| 방 입장 · 플레이 · 채팅 | ✅ | ✅ |
| 닉네임 | 임시 (랜덤 부여, 수정 가능) | 고정 |
| 전적 · 랭킹 | ✕ | ✅ |
| 데일리 싱글 기록 | 로컬만 | 서버 저장 |
| 방 만들기 | ✅ | ✅ |

가입 유도는 **결과 화면에서 한 번만**: `이 기록을 저장할까요?`

## 9. 게임 모듈 인터페이스

방 껍데기는 공통이고 게임만 갈아 끼운다. 03·05 문서와 연결된다.

```ts
export interface RoomGame<Question, Answer> {
  id: string                       // 'geuhae' | 'chosung' | 'assoc'
  meta: {
    name: string
    minPlayers: number             // 그 해 2 · 초성 2 · 단어연상 3
    maxPlayers: number
    roundMs: number
    hasPresenter: boolean          // 단어 연상만 true
  }

  // ── 순수 함수. WebSocket도 DO도 모른다 ──
  createRound(seed: string, roundNo: number, ctx: ContentCtx): Question
  judge(q: Question, playerId: string, text: string, atMs: number): Judgement
  isRoundOver(q: Question, state: RoundState): boolean
  reveal(q: Question): RevealData          // 정산 화면 데이터

  // 참가자별 뷰 — 정답이 새면 안 된다 (출제자는 예외)
  viewFor(q: Question, state: RoundState, playerId: string): PlayerView

  // 화면
  Board: React.ComponentType<BoardProps>   // 문제 영역
}
```

**`judge`가 채팅 메시지를 그대로 받는다.** 정답 입력이 곧 채팅이라는 설계가 인터페이스에 그대로 드러난다.

**`viewFor`가 필수인 이유**: 단어 연상에서 출제자는 정답을 알고 나머지는 몰라야 한다. 참가자별로 다른 뷰를 만드는 건 게임 모듈의 책임이다.
