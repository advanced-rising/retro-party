# 07. 게임 라인업

> 「그 해」는 1번일 뿐이다. 이 문서는 **2번 이후에 뭘 얹을지**와,
> **얹는 게 실제로 쉬운지**를 다룬다.

## 1. 게임을 고르는 기준

00 문서의 성공 조건을 게임 단위로 옮긴 것이다. 새 게임 후보는 이 표를 통과해야 한다.

| # | 기준 | 왜 |
|---|---|---|
| 1 | **설명이 한 줄** | 메뉴에서 번호 누르고 바로 이해돼야 한다 |
| 2 | **1~3분에 끝난다** | 데일리의 전제 |
| 3 | **점수화·랭킹이 자연스럽다** | 플랫폼이 주는 것을 쓸 수 있어야 한다 |
| 4 | **데이터가 공짜거나 자체 생산 가능** | 라이선스 병목 = 프로젝트 병목 |
| 5 | **공유하고 싶어진다** | 자랑 or 억울함이 있어야 한다 |
| 6 | **기존 게임과 형태가 다르다** | 같은 형태 두 개는 하나만 못하다 |

6번이 특히 중요하다. 「그 해」가 **추론형·시간무제한**이므로, 다음은 **반사신경형·시간제한**이어야 한다.

## 2. 라인업

### #1 「그 해」 — 데일리 추론 ✅ Phase 1

힌트를 열어가며 연도를 맞힌다. 01 문서.

- 형태: 추론 · 시간 무제한 · 2~3분
- 데이터: 공공 통계 + AI 생성 (02 문서)

### #2 「맞춤법 지옥」 — 60초 아케이드 ⏳ Phase 2

```
  ╔═══════════════════════════════════════════════╗
  ║  맞춤법 지옥                        ⏱ 00:47   ║
  ╠═══════════════════════════════════════════════╣
  ║                                               ║
  ║   회의가 잘 되서 다행이야                      ║
  ║        ────                                   ║
  ║   틀린 곳을 고르세요                           ║
  ║                                               ║
  ║   1. 회의가    2. 잘    3. 되서    4. 다행이야 ║
  ║                                               ║
  ╠═══════════════════════════════════════════════╣
  ║   12 / 25 정답        연속 8        점수 840  ║
  ╚═══════════════════════════════════════════════╝
```

60초에 문제 25개. 문장에서 틀린 곳을 고른다.

| 기준 | 평가 |
|---|---|
| 설명 한 줄 | ✅ "틀린 맞춤법을 찾으세요" |
| 1~3분 | ✅ 60초 |
| 점수화 | ✅ 정답 수 + 속도 |
| 데이터 | ✅ 자체 제작. 국립국어원 어문규범이 근거 |
| 공유 | ✅ **전국민이 자기가 잘한다고 믿고 실제론 못한다** |
| 형태 차별 | ✅ 반사신경 · 시간제한 — 「그 해」의 정반대 |

**왜 2번인가**: 「그 해」와 형태가 완전히 달라서 플랫폼 구조를 제대로 시험한다. 데이터 리스크도 0에 가깝다.

**리스크**: 애매한 문제 하나가 커뮤니티에서 물어뜯긴다. 모든 문제에 **어문규범 근거를 붙이고**, 논쟁적인 것(사이시옷 일부, 외래어 표기)은 제외한다.

**콘텐츠**: 문제 800개 목표. 「그 해」와 같은 파이프라인을 쓰되, 검증은 국립국어원 규범 대조로 단순하다.

### #3 「전국구」 — 지도 스피드 ⏳ Phase 3

```
  ╔═══════════════════════════════════════════════╗
  ║  전국구                     15 / 15   ⏱ 00:23 ║
  ╠═══════════════════════════════════════════════╣
  ║                                               ║
  ║          [ 대한민국 지도 ]                     ║
  ║                                               ║
  ║       "구 미 시"  를 찍으세요                  ║
  ║                                               ║
  ╠═══════════════════════════════════════════════╣
  ║   평균 오차 18km        누적 점수 1,240        ║
  ╚═══════════════════════════════════════════════╝
```

지명을 주면 지도에서 찍는다. 오차 거리로 채점. 60초에 15개.

| 기준 | 평가 |
|---|---|
| 설명 한 줄 | ✅ |
| 데이터 | ✅ 행정구역 좌표 = 공공데이터 |
| 공유 | ✅ 자기 고향 못 맞히면 억울함 |
| 형태 차별 | ✅ **공간 인터랙션** — 앞의 둘과 또 다름 |

**레트로 레이어**: `1995년 행정구역으로 풀기` 모드. 직할시→광역시 전환, 시군 통합 이전 지도. 이게 붙으면 플랫폼 정체성과 맞아떨어진다.

**리스크**: 지리 퀴즈는 이미 많다. 시대 레이어가 차별점의 전부다.

### #4 「그때 그 값」 — 가격 맞추기 ⏳ 후보

```
   1994년       "새우깡 한 봉지"

   ┌──────────────────────────────────┐
   │  100원          ●          2,000원│
   └──────────────────────────────────┘
              슬라이더로 맞추세요
```

연도를 주고 물건 가격을 맞춘다. 오차율로 채점.

- **「그 해」와 데이터를 완전히 공유한다** (`facts` 테이블의 price 카테고리)
- 콘텐츠 추가 비용이 사실상 0
- 형태는 다르다 (슬라이더 추정 vs 추론)
- 단점: 「그 해」와 소재가 겹쳐서 신선도가 낮을 수 있음

**저비용 고효율 후보.** Phase 2~3에서 여유가 생기면 2주 안에 만들 수 있다.

---

### #5 「연표 정렬」 — 순서 맞추기 ⏳ 후보

사건 카드 5장을 시간순으로 배열. 60초에 8세트.

- 데이터 공유 가능 (`facts`)
- 드래그 인터랙션 — 또 다른 형태
- 단점: 훅이 약하다. 공부 느낌

---

### #6 「받아쓰기」 — 듣고 입력 ⏳ 후보

TTS로 문장을 읽어주고 받아쓴다. 맞춤법 + 타이핑.

- 데이터: TTS 생성 → 비용 낮음
- **접근성 이슈** (청각) — 별도 모드 필요
- 타이핑 게임은 메트로타이핑 영역과 겹침

## 3. 만들지 않을 것

| 후보 | 왜 안 하나 |
|---|---|
| 사진 보고 시대 맞추기 | **이미지 저작권**. 아이디어는 좋지만 실행 불가 (이전 검토에서 결론) |
| 옛날 노래 인트로 맞추기 | 음원 저작권. 불가 |
| 옛날 광고 영상 퀴즈 | 영상 저작권. 불가 |
| 인물 사진 맞추기 | 초상권 + 저작권 |
| 실시간 대전 전용 게임 | 데일리 플랫폼과 리듬이 안 맞음 |

**저작권이 걸리는 소재는 처음부터 제외한다.** 이 프로젝트가 텍스트 중심인 이유다.

## 4. 새 게임 추가 절차

03 문서 §3의 모듈 구조가 실제로 이걸 가능하게 하는지가 관건이다.

### 4.1 파일

```
packages/games/{gameId}/
├─ index.ts        GameModule 구현 (createDaily / validate / score / redact)
├─ client.tsx      게임 화면
├─ share.ts        공유 카드
└─ schema.ts       payload 타입

apps/web/lib/registry.ts    한 줄 추가
```

DB 마이그레이션 **없음** — 게임별 데이터는 `plays.result` JSONB에 들어간다.

### 4.2 자동으로 붙는 것

- PC통신 메뉴 등록 (`meta.order`)
- 라우팅 `/g/{gameId}`
- 데일리 퍼즐 Cron
- 계정 · 게스트 세션
- 점수 제출 · 랭킹 (게임별 + 통합)
- 스트릭
- 공유 카드 (텍스트 + 이미지)
- 오류 신고 창구

### 4.3 체크리스트

새 게임을 만들 때:

- [ ] §1의 6개 기준을 통과하는가
- [ ] `redact()`가 정답을 완전히 제거하는가 (테스트 필수)
- [ ] `Date.now()` / `Math.random()`을 쓰지 않는가
- [ ] 데이터 라이선스가 깨끗한가
- [ ] 기존 게임과 형태가 다른가
- [ ] 콘텐츠 초기 물량과 지속 보강 계획이 있는가
- [ ] 접근성 — 시간 제한이 있다면 완화 모드가 있는가

### 4.4 목표

**두 번째 게임 구현에 3주 이내.** 넘어가면 모듈 인터페이스가 잘못된 것이다 (05 문서 G2).

## 5. 게임 간 시너지

플랫폼의 진짜 가치는 게임을 나열하는 게 아니라 **엮는** 데서 나온다.

| 장치 | 내용 |
|---|---|
| **통합 스트릭** | 어떤 게임이든 하루 하나 하면 유지. 다른 게임으로 유도 |
| **오늘의 3판** | 세 게임을 다 하면 보너스 배지 |
| **데이터 공유** | 「그 해」의 `facts`를 「그때 그 값」·「연표 정렬」이 재사용 |
| **통합 랭킹** | 게임별 순위의 합산 — 만능형 플레이어를 위한 지표 |
| **연대기 프로필** | "1997년 문제를 8번 만났고 6번 맞혔습니다" 같은 개인 통계 |

**통합 스트릭이 가장 강력하다.** 「그 해」를 이미 푼 사람이 스트릭을 지키려고 다른 게임을 열어보게 된다.

## 6. 라인업 로드맵

```
Phase 1   #1 그 해                        데일리 추론
Phase 2   #2 맞춤법 지옥                  60초 아케이드      ← 플랫폼 검증
Phase 3   #3 전국구                       지도 스피드
Phase 3~4 #4 그때 그 값                   슬라이더 추정 (저비용)
Phase 4   #5~ 후보군에서 선택
```

**게임 6개가 상한선**이다. 그 이상은 메뉴가 무너지고 유저가 뭘 할지 못 고른다.
6개를 채우면 새 게임 대신 **기존 게임의 모드 확장**으로 간다.

## 7. 열려 있는 결정 사항

| # | 항목 | 비고 |
|---|---|---|
| G1 | 2번 게임을 맞춤법으로 확정할 것인가 | 형태 차별성은 최고. 다만 콘텐츠 800건이 또 필요 |
| G2 | 「그때 그 값」을 2번으로 앞당길 것인가 | 데이터 공유로 훨씬 싸다. 대신 형태 차별성 낮음 |
| G3 | 통합 스트릭 vs 게임별 스트릭 | 통합이 유도 효과 크지만 각 게임의 데일리 압력이 약해짐 |
| G4 | 게임 상한 6개가 맞는가 | 메뉴 UI의 물리적 한계 |
