## 2. L1 — AI 생성 힌트의 사실 오류 🔴

**이 제품의 최대 리스크다.** 법적 문제이기 이전에 제품 생존의 문제다.

### 왜 심각한가

- 게임의 전제가 "이 정보는 사실이다"이다. 틀리면 게임이 성립하지 않는다
- 향수 콘텐츠는 **당사자들이 직접 겪은 일**이라, 틀리면 즉시 발각된다
- 커뮤니티 확산이 성장 전략인데, 오류는 그 확산 경로를 그대로 타고 퍼진다
- LLM은 특히 **연도를 자주 틀린다** — 하필 이 게임의 정답이 연도다

### 대응 (02 문서에 구현)

| 층위 | 조치 |
|---|---|
| 생성 | 출처 URL 필수, 구조화 출력, `confidence` 자기 평가 |
| 검증 A | 공공 API 자동 대조 (수치형은 정답이 존재) |
| 검증 B | 생성과 분리된 독립 세션에서 교차 확인, 소스 2개 이상 |
| 검증 C | 문화형은 사람 검수 + 단정하지 않는 톤 |
| 게이트 | 배포 전 200건 전수 검수, **연도 오류 < 0.5%** |
| 운영 | 신고 즉시 비활성화 → 24시간 내 처리 → 수정 이력 공개 |

### 운영 원칙

**"먼저 내리고 나중에 확인한다."** 신고가 들어오면 사실 확인 전에 먼저 비활성화한다.
틀린 힌트가 하루 더 노출되는 비용이, 맞는 힌트가 하루 빠지는 비용보다 훨씬 크다.

### 고지

```
힌트는 공공 통계와 공개 자료를 바탕으로 작성했습니다.
오류를 발견하시면 신고해 주세요. 확인 후 24시간 내에 수정합니다.
```

수정 이력을 공개 페이지에 남긴다. **틀렸을 때 빨리 고치는 모습이 신뢰를 만든다.**

## 3. L2 — 뉴스·저작물 인용 🟡

### 문제

힌트 생성 과정에서 웹검색으로 언론 기사를 읽는다. 기사 제목·본문은 저작물이다.

### 대응

- **원문을 복제하지 않는다.** 사실을 추출해 자체 문장으로 재작성 (02 문서 §7)
- 사실 자체(`1997년 자장면 2,500원`)에는 저작권이 없다
- `sources`는 **참조 링크로만** 보관. 서비스 화면에 원문을 표시하지 않는다
- 웹페치로 가져온 원문은 **검증 과정에서만 사용**하고 DB에 저장하지 않는다
- 광고 카피, 유행어 등 창작성이 있는 짧은 문구는 주의:
  - 광고 카피는 **짧은 문구라 저작물성이 부정될 여지가 크지만**, 상표로 등록된 슬로건은 별개
  - 안전하게 가려면 카피를 그대로 쓰지 않고 `"이 해 화제가 된 광고 문구"` 정도로 우회
- 가사·시·소설 인용은 **하지 않는다**. 카테고리에서 제외

### 확인 필요

1. 광고 카피 카테고리를 유지할 것인가 (재미 vs 리스크)
2. "이 해 최고 시청률 드라마 — 「모래시계」" 처럼 **작품 제목**을 쓰는 것 — 제목은 원칙적으로 저작물이 아니나, 상표 등록 여부 확인

## 4. L3 — 서비스명 / 상호 충돌 🟡

「한별정보통신」은 그럴듯한 만큼 **실존 법인이 있을 가능성이 있다.**

### 대응

Phase 0에서 반드시:
- [ ] 키프리스(KIPRIS) 상표 검색 — 9류(소프트웨어), 41류(교육·오락)
- [ ] 법인 등기 상호 검색 (대법원 인터넷등기소)
- [ ] 도메인 확보: `hanbyul.kr` / `hanbyul.io` 등
- [ ] SNS 핸들 선점

충돌이 발견되면 대안: 「나우별」「새롬통신」「청람정보통신」 등 조합 변경.
**가상 PC통신이라는 컨셉만 지키면 이름은 대체 가능하다.**

- 서비스 내 **"본 서비스는 가상의 PC통신 컨셉이며 실존 기업과 무관합니다"** 고지
- 상표 출원은 Phase 2 이전에 (알려진 뒤엔 늦다)

## 5. L4 — 게임물 등급분류 🟡

### 판단

게임산업진흥법상 국내 유통 게임물은 등급분류 대상이다.

- 웹 기반 게임도 대상
- 사행성 요소 없음 → 등급 자체는 문제되지 않을 것 (전체이용가)
- 퀴즈/추론 게임이므로 선정성·폭력성 이슈 없음

### 대응

- Phase 1 런칭 전 게임물관리위원회에 필요 여부 문의
- 필요 시 등급분류 신청 (수수료 저렴, 절차 단순)
- 게임 재화 판매·확률형 아이템 없음 (00 문서 §8에서 이미 배제)

## 6. L5 — 개인정보 🟡

### 수집 항목

| 항목 | 목적 | 비고 |
|---|---|---|
| 소셜 ID / 이메일 | 계정 식별 | 최소 스코프만 |
| 닉네임 | 랭킹 표시 | |
| **연령대** (10대~60대) | 세대별 통계 콘텐츠 | **선택 입력** ⚠️ |
| 플레이 기록 | 스트릭, 랭킹, 난이도 보정 | |
| 접속 IP·UA | 어뷰징 방지 | 3개월 |

### 연령대 수집 주의

세대 비교가 이 게임의 핵심 재미 요소지만(01 문서 §4.1), 연령 정보는 개인정보다.

- **반드시 선택 입력.** 안 넣어도 게임은 완전히 동작한다
- 10년 단위 구간만 받는다 (생년월일 X)
- 통계는 **구간별 5명 이상일 때만** 표시 (역추적 방지)
- 수집 목적을 화면에서 명시: `"세대별 통계를 보여드리기 위해 사용합니다"`

### 만 14세 미만

향수 게임이라 주 이용층은 성인이지만, 학교에서 쓸 가능성이 있다.
**법정대리인 동의 절차 또는 14세 미만 가입 제한 중 택일**을 Phase 2 전에 확정한다.

### 기타

- 개인정보처리방침 / 이용약관 게시
- 게스트 플레이는 개인정보 수집 없음 (익명 세션 ID만)
- Cloudflare·PostgreSQL 리전에 따라 **국외 이전 고지** 필요 여부 확인

## 9. L8 — 실존 인물·기업 언급 🟢

힌트에 실존 기업·연예인·운동선수가 등장한다 (`H.O.T 데뷔`, `해태 타이거즈 우승`).

### 판단

- **역사적 사실의 서술은 문제되지 않는다.** 상표적 사용이 아니다
- 로고·이미지는 **사용하지 않는다.** 텍스트만
- 부정적 맥락(부도, 사건사고)은 **취급을 신중히**:
  - 기업 부도 등은 공적 사실이라 서술 가능
  - 개인의 사건·사고, 범죄, 사생활은 **카테고리에서 제외**
  - 고인이나 유족에게 상처가 될 수 있는 사건은 힌트로 쓰지 않는다

### 힌트 제외 규칙 (파이프라인에 명시)

```
다음은 힌트로 생성하지 않는다:
  · 개인의 사망, 사고, 범죄, 질병
  · 재난·참사 (희생자가 있는 사건)
  · 개인의 사생활, 스캔들
  · 특정 집단에 대한 비하가 될 수 있는 유행어
```

**재난·참사를 퀴즈 소재로 쓰지 않는다.** 이건 법적 문제 이전에 태도의 문제다.
그 해를 설명할 때 반드시 필요하다면 「그 해」 요약 카드의 서술로만 담고, **맞히기 힌트로는 쓰지 않는다.**

## 11. L10 — 대전 채팅 (휘발형) 🟡

Phase 3에 대전과 함께 채팅이 들어온다 (08 문서 §6). **대화를 저장하지 않는 설계**라 리스크 구조가 일반적인 채팅과 다르다.

### 저장 안 함이 유리하게 작용하는 부분

| 항목 | 효과 |
|---|---|
| 개인정보 보관 | 대화 본문을 **수집하지 않으므로** 처리 항목에서 빠진다 |
| 유출 사고 | 없는 데이터는 새지 않는다 |
| 파기 의무 | 보관하는 게 없으니 파기 절차도 없다 |
| 열람·삭제 요구 | 응할 대상 자체가 없다 |

**단, 신고 시 첨부되는 직전 20줄은 저장된다.** 이건 개인정보처리방침에 별도로 명시한다.

```
· 수집 항목: 신고 시 신고자가 첨부한 대화 내용 (최대 20줄)
· 수집 목적: 신고 검토
· 보관 기간: 검토 완료 후 30일, 이후 자동 파기
```

### 저장 안 함이 불리하게 작용하는 부분

**사후 조치 근거가 약하다.** 욕설 신고가 들어와도 서버 측 원본이 없다.

대응 (08 문서 §6.3):
- 신고 첨부 대화는 **증거가 아니라 검토 시작점**으로만 쓴다 (신고자가 조작 가능)
- 실제 제재는 **서버 측 신호**로 판단: 금칙어 필터 차단 횟수, 반복 신고 누적, 도배 차단 이력
- 이 신호들은 **본문 없이 카운터만** 저장하므로 휘발 원칙과 충돌하지 않는다

### 청소년 보호

낯선 사람과의 자유 채팅이 가장 큰 리스크다. 설계로 차단한다:

| 모드 | 채팅 |
|---|---|
| 친구 초대 대전 | 자유 채팅 (서로 아는 사이) |
| **랜덤 매칭** | **자유 채팅 없음. 정형 이모트 6종만** |

랜덤 매칭에서 자유 입력을 아예 막으면 그루밍·유해 접촉 경로가 구조적으로 사라진다.

### 게임물 등급분류 재확인 필요

**채팅 기능의 유무는 등급분류에서 중요 항목이다.** L4에서 Phase 1에 문의할 때 "현재 채팅 없음, Phase 3에 휘발형 채팅 도입 예정"을 함께 알리고, 도입 시점에 등급 재검토가 필요한지 확인한다.

### 확인 필요

1. 휘발성 1:1/소규모 대화가 정보통신망법상 **게시판 운영자 의무** 대상인지 (사적 대화에 가까워 보이나 확인 필요)
2. 채팅 도입 시 게임물 등급 재분류가 필요한지
3. 신고 첨부 대화의 보관 기간 30일이 적절한지
