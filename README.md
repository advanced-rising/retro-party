# 손이심심 — 90년대로 노는 실시간 방 게임

> 손이 심심할 때 들어오면 사람들이 있고, 채팅으로 답을 외치고, 라운드가 계속 돈다.
> 큐플레이 · 캐치마인드 · 쿵쿵따의 그 감각. **소재는 90년대, UI는 2026년.**
>
> 참가자는 전부 실제 사람이다. 봇으로 방을 채우지 않는다.

## 뭘 만드나

**실시간 방이 본체**이고, 싱글과 랭크가 그 앞뒤를 받친다.

| | |
|---|---|
| 형태 | **방 정원 8명**, 라운드 10회, 한 판 8~12분 |
| 입력 | **채팅창이 곧 정답 입력창** |
| 소재 | 1980~2000년대 한국 (물가·문화·물건·유행어) |
| 목표 | 사람들이랑 왁자지껄 떠드는 재미 |

### 모드

```
싱글                     멀티                          랭크
──────────────────      ──────────────────────       ──────────────────
데일리  하루 1회      캐주얼방  개인전            데일리 랭킹
연습    무한          팀전      2v2·3v3·4v4         싱글 기반 · Phase 1
                        랭크전    매칭 · 승점       티어 · 시즌
                                                        멀티 기반 · Phase 3
```

- **싱글**이 없으면 새벽 3시에 온 사람이 빈 방을 보고 영영 떠난다
- **팀전 4:4**는 실력 편차를 덮어준다 — 혼자 꼴찌면 나가지만 팀에는 묻어간다
- **랭크**가 없으면 한 달 하고 질린다

진행 축은 셋이고 각각 다른 질문에 답한다 (10 문서):

```
레벨 1~100   누적, 안 떨어짐      →  "얼마나 했나"
칭호         수집·장착            →  "뭘 했나"      [초딩] [연상왕] [호구]
랭크 5급~유단자  시즌 리셋         →  "얼마나 잘하나"
```

팀전은 **팀 채팅을 분리**해야 성립한다. 전체 채팅에 답을 치면 상대 팀이 그대로 보기 때문이다 (01 문서 §6.5).
그리고 **개인전 8명보다 팀전 4:4가 오히려 쾌적하다** — 채팅이 4명씩 갈려 읽을 수 있게 된다.

### UI 원칙: 이모지를 쓰지 않는다

아바타 · 순위 · 상태 · 이모트 전부 **아이콘 또는 텍스트**다. 이모지는 OS마다 다르게 보이고 색을 통제할 수 없어서 팀 색·출제자 보라 같은 시맨틱 컬러를 못 입힌다.

아바타는 **Phosphor 아이콘 + 배경색**이고, 아이콘을 `cassette-tape` `floppy-disk` `game-controller` 같은 **90년대 물건**으로 골라 정체성을 만든다 (06 문서 §4.2~4.3).

## 이 프로젝트의 가장 큰 위험

**동시 접속자가 없으면 게임이 성립하지 않는다.**

Wordle은 유저가 1명이어도 돌아가지만 이건 아니다. 빈 방 목록을 본 사람은 즉시 나가고 다시 오지 않는다. 이 장르가 죽는 이유는 거의 항상 이것이다.

그래서 **콜드스타트 대응이 기획의 절반**이다 — [03 문서](docs/03-cold-start.md)가 그것만 다룬다.

## 기술 스택

```
Cloudflare Workers ── Next.js (OpenNext)     화면 / SSR / OG
Cloudflare Workers ── API                    인증 · 방 목록 · 기록
Durable Objects ★                            게임방 · 로비 · 실시간 WebSocket
KV · R2 · Queues · Cron · Turnstile
        │  Hyperdrive
PostgreSQL           계정 · 전적 · 랭킹 · 콘텐츠 DB
        │
NestJS  (Phase 2~)   콘텐츠 배치 · 관리자
```

**게임 서버는 Durable Objects다.** 방 하나 = DO 인스턴스 하나.
런타임에 LLM을 호출하지 않는다 — 방에서 벌어지는 모든 일은 사전 생성된 데이터와 순수 로직으로 돌아간다.

## 실행

```bash
pnpm install

pnpm --filter @retro/api dev      # 게임 서버 (Durable Objects)  :8787
pnpm --filter @retro/web dev      # 화면                          :3000
```

브라우저 두 개로 `http://localhost:3000` 을 열고 [바로 참가] → 방 코드를 공유하면
한 방에서 붙습니다. 2명부터 시작됩니다.

## 검증 도구

**눈으로 판단하지 않는다.** 전부 실패하면 exit 1 로 떨어진다.

```bash
pnpm typecheck    # tsc --build (strict + noUncheckedIndexedAccess 등)
pnpm test         # 117건 — 정답 누출 · 팀 채널 격리 · 재접속 · 스킵/힌트 투표
pnpm content      # 문항 599개 검증 — 정답 누출 · 중복 · 근거 유무
pnpm contrast     # 컬러 토큰 대비 (WCAG AA / 1.4.11) — 32건
pnpm smoke        # 서버를 띄운 뒤 Phase 0.5 관문 실측
```

`pnpm smoke` 가 재는 것 (07 문서 §G0.5)

| 항목 | 기준 | 실측 |
|---|---|---|
| 8명 동시 접속 | 8소켓 | 61ms |
| 9번째 입장 | 거절 | `room_full` |
| 채팅 왕복 | p95 < 150ms | p50 4.4ms · p95 47.7ms |
| board 정답 누출 | 없음 | 없음 |
| 진행 중 재접속 | 점수·자리 유지 | 유지 |
| 팀 채널 격리 | 상대 팀 미수신 | 같은 팀 2명만 |

## 현재 상태

**Phase 0.5 관문 통과.** 게임 4종으로 8명이 한 방에서 실제로 한 판을 돌린다.

```
packages/types        브랜디드 ID · 방 · 방 목록 · WebSocket 프로토콜 + 런타임 파서
packages/room-kit     방 상태 머신 · 판정 · 팀 편성 · 채팅 · 시드 난수
                      client-state — 서버 메시지를 화면 상태로 접는 순수 리듀서
packages/games/       chosung  초성 퀴즈      20초
                      geuhae   그 해          60초
                      assoc    단어 연상      90초 (출제자 · 혼자 모드)
                      mulga    그때 그 가격    40초
apps/api              Worker + RoomDO(방) + LobbyDO(목록)
apps/web              Next.js — 첫 화면 · 방 · 4종 보드
tools/                contrast · smoke · bots
```

**개발용 임시 플레이어** — 혼자서도 방을 돌려볼 수 있다.

```bash
pnpm bots ABCDEF 4      # 방 코드에 4명 붙인다
```

서버에 가짜 참가자를 만드는 코드는 없다. 이 봇들은 브라우저와 똑같이
WebSocket 으로 붙는 진짜 클라이언트라서, 서버는 사람과 구별하지 못한다.
